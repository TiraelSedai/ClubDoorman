# Сопоставление Telegram-ссылок из описаний пользователей

Проверено 7 сентября 2026 года по официальной документации Telegram.

## Практический вывод

Bot API позволяет точно сопоставить одинаковый invite hash и публичные ссылки, для которых он вернул одинаковый `chat.id`.
Произвольные разные приватные приглашения невозможно гарантированно свести к одной группе только через Bot API.
Даже отдельная пользовательская MTProto-сессия не гарантирует получение ID группы без вступления: обычный результат `chatInvite` не содержит этого поля.
Это ограничение точного определения ID группы через API; оно не препятствует получению веб-превью и эвристическому сопоставлению его содержимого.

## Что предоставляет API

- [`getChat`](https://core.telegram.org/bots/api#getchat) принимает числовой ID либо `@username` супергруппы или канала; параметра invite hash нет.
- Возвращаемый [`ChatFullInfo`](https://core.telegram.org/bots/api#chatfullinfo) содержит уникальный `id`, опциональные `active_usernames` и `bio`; разные публичные имена можно сопоставлять по возвращённому ID.
- [`messages.checkChatInvite`](https://core.telegram.org/method/messages.checkChatInvite) принимает hash и доступен только пользовательским аккаунтам, поэтому авторизация ботом через MTProto ограничение не снимает.
- [`chatInvite`](https://core.telegram.org/constructor/chatInvite) содержит заголовок, описание, фото и сведения об участниках, но не содержит `chat` или `chat_id`.
- [`chatInviteAlready`](https://core.telegram.org/constructor/chatInviteAlready) возвращает `chat`, когда пользователь уже вступил в группу.
- [`chatInvitePeek`](https://core.telegram.org/constructor/chatInvitePeek) также возвращает `chat`, но означает временный доступ на чтение до `expires`.
- Telegram [документирует](https://core.telegram.org/api/invites) возможность `chatInvitePeek` только для супергрупп и каналов, а не обязательную выдачу такого результата для каждого приглашения.
- [`messages.importChatInvite`](https://core.telegram.org/method/messages.importChatInvite) вступает в группу и доступен только пользователям; приглашения могут требовать одобрения, оплаты или быть просроченными, а число подписок ограничено.

Следовательно, автоматическое вступление пользовательским аккаунтом было бы отдельным поведением сервиса, а установка MTProto-библиотеки сама по себе задачу не решает.
Сходство названия, описания и фото не подтверждает одинаковый `chat.id`; такое сравнение можно обозначать только как эвристику.

## Нормализация ссылок

Telegram [документирует](https://core.telegram.org/api/links#chat-invite-links) эквивалентные формы `t.me/+<hash>`, `t.me/joinchat/<hash>` и `tg://join?invite=<hash>`.
В качестве ключа точного совпадения достаточно выделенного hash без изменения его регистра.
Также поддерживаются домены `telegram.me` и `telegram.dog`, варианты HTTP/HTTPS и ссылки без схемы; фрагмент URL игнорируется согласно [правилам deep links](https://core.telegram.org/api/links).
Ссылки `t.me/+<phone_number>` ведут к пользователям, поэтому числовой телефон нельзя автоматически считать приглашением в группу.
Публичную ссылку следует считать группой или каналом после успешного разрешения через `getChat` с соответствующим типом результата.

## Применимость к ClubDoorman

В [проекте](../../ClubDoorman/ClubDoorman.csproj) уже есть `Telegram.Bot` версии `22.*`; MTProto-клиента среди зависимостей нет.
[AiChecks](../../ClubDoorman/AiChecks.cs) уже получает `ChatFullInfo` и читает `Bio`, поэтому одинаковые приглашения можно сопоставлять без нового Telegram-клиента.
Для разных приватных hash нужен источник подтверждённого соответствия `hash -> chat.id`, например заранее установленное соответствие или отдельный пользовательский сервис с фактическим доступом к группе.
Без такого источника совпадение разных приглашений определяется эвристически по содержимому веб-превью, без утверждения о подтверждённом `chat.id`.

## Веб-превью приглашения

7 сентября 2026 года обычный HTTPS-запрос к [приглашению из примера](https://t.me/+xsvOr9vFZWUyOWNi) вернул название «6 Figs soon…», описание «Иногда любим MEXC всей душой иногда ненавидим😁» и фотографию с CDN Telegram.
Для этого не понадобились Bot API, пользовательская сессия или вступление в канал.
Несуществующее тестовое приглашение вернуло HTTP 200 и общую страницу приглашения без `.tgme_page_title`; такая страница не содержит данных конкретной группы и не участвует в сопоставлении по содержимому.
HTML-фрагменты обеих страниц сохранены в `ClubDoorman.Test/Fixtures/telegram-invite-*.html` с сокращённым CDN-адресом фотографии.
Это наблюдаемое поведение сайта, а не версионированный контракт API.

`TelegramInvitePreviews` разбирает HTML через [AngleSharp](https://github.com/AngleSharp/AngleSharp).
Из `.tgme_page_title` и `.tgme_page_description` извлекается текст с декодированными HTML-сущностями; переносы `<br>` сохраняются.
Фотография скачивается из `.tgme_page_photo_image`; общий логотип Telegram из Open Graph не используется вместо отсутствующей фотографии группы.
Сетевой клиент не следует редиректам и получает фотографии только по HTTPS с `t.me` или поддоменов `telesco.pe`.

## Реализация контекста и предупреждения

`TelegramInvitePreviews` используется и `MessageProcessor`, и `ProfileInputCollector` через общий часовой кэш в памяти.
`AiChecks` добавляет название, описание и само изображение приглашённой группы в пользовательские сообщения для LLM.
Хеш изображения участвует в ключе кэша AI-вердикта; изменение любого из трёх полей меняет этот ключ после обновления превью.
Адрес CDN не входит ни в содержимое промпта, ни в ключ сопоставления.
Число участников или подписчиков нигде не извлекается и не учитывается, даже как дополнительный признак.

Отпечаток группы вычисляется как SHA-256 от JSON-массива `[название, описание, SHA-256(байты фото)]`.
JSON сохраняет границы полей без неоднозначности конкатенации.
Если у группы нет фотографии, третье поле равно `null`.
Сравнение фотографии точное, по байтам; перекодированное изображение может дать другой хеш даже при внешнем сходстве.
Если заявленная фотография не скачалась, неполное превью не получает отпечаток без фото: запрос повторится при следующей проверке.
При сетевой ошибке продолжает работать сопоставление одинаковых invite hash; ошибка не кэшируется как успешное пустое превью.
Некорректные байты изображения или недопустимый адрес фото завершают проверку ошибкой, а не превращаются в пустое превью.

`BioInviteTracker` сопоставляет и точные invite hash, и отпечатки разных приглашений.
История хранится в памяти за последние 24 часа и сбрасывается при перезапуске.
Совпадение требует разных пользователей, но допускает один и тот же чат и разные тексты сообщений.
При первом совпадении предупреждения получают сообщения обоих пользователей; для уже отмеченного пользователя в том же чате повторный репорт подавляется.
Точное совпадение инвайта и совпадение его содержимого используют общее состояние предупреждения, чтобы не репортить одного пользователя дважды за одно наблюдение.
На время отправки предупреждение резервируется, чтобы параллельные обновления не создавали дубли.
Отправленным оно считается только после успешного запроса к Telegram.
Ошибка или отмена освобождает неотправленную часть пакета для повторной попытки при следующем совпадении; успешно отправленные предупреждения остаются подавленными.
Состояние доставки передаётся между инвайтами одной группы по ссылке, поэтому ротация инвайта во время отправки не теряет результат этой отправки.
Новый пользователь или появление известного пользователя в другом чате создаёт новый репорт.
Для каждого пользователя в каждом чате сохраняется последнее наблюдение; новая активность продлевает срок его хранения.
Репорт по содержимому говорит о вероятной общей группе и содержит оба инвайта и ссылку на сообщение другого пользователя.
Одинаковое оформление двух разных групп может дать ложное совпадение, поэтому этот сигнал остаётся предупреждением.

Репорты идут через существующий `DontDeleteButReportMessage` только в админ-чаты PRO-групп.
Проверка работает на этапе проверки био после содержимого сообщения и исключения доверенных пользователей из модерации.
Само совпадение не удаляет сообщения и не банит пользователей, но не позволяет засчитать текущее сообщение как хорошее для автоматического доверия.
Публичные username не входят в этот механизм сопоставления; их существующий контекст в AiChecks сохраняется.
